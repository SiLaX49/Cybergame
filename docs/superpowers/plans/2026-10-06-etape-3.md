# Étape 3 : thèmes sensibles — plan d’implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** écrire et rendre jouables (en brouillon) les 6 missions des thèmes sensibles « Cyberharcèlement » et « Rencontres en ligne », avec 5 leviers et 2 actions de récupération nouveaux, et un filtre de publication : une mission sensible n’apparaît en ligne qu’après la relecture interne renforcée (statut `relue-interne`).

**Architecture :** un champ `relecture` sur les missions ; `buildContent` exclut les brouillons sensibles en production (option `brouillons`) ; un bandeau « Brouillon » dans la mission et la fiche ; 5 leviers ajoutés à `LEVIERS` et `content/leviers.yaml` ; 2 composants de récupération ; règles éditoriales vérifiées par des tests ; un script d’export Markdown pour la relecture humaine. Le contenu est livré au statut `a-relire` : il n’apparaît pas sur le site tant que Noa ne l’a pas relu.

**Tech Stack :** Vue 3.5, TypeScript 5.9, Zod 4, Vitest 5, Playwright + axe ; ajout de `tsx` (devDependency) pour le script d’export.

**Spec :** `docs/superpowers/specs/2026-10-05-etape-3-design.md` (statut validé, § 10 tranché).

## Global Constraints

- Branche `feat/etape-3` (depuis `main` 9808b47). Messages de commit conventionnels terminés par la ligne `Co-Authored-By: Claude … <noreply@anthropic.com>` fournie par la session.
- Textes visibles en français avec l’apostrophe typographique `’` (U+2019), saisie comme vrai caractère.
- Tout au clavier ; aucune information par la couleur seule ; focus géré à chaque changement d’état (`src/ui/focus.ts`).
- **Aucune mission sensible au statut `a-relire` dans le build de production** (GitHub Pages). En développement et pour les tests E2E (`VITE_BROUILLONS=1`), elles sont incluses avec le bandeau « Brouillon : contenu pas encore relu, ne pas utiliser en classe ».
- Toutes les missions de cette étape sont livrées au statut `a-relire`. Passer une mission en `relue-interne` est une décision humaine, hors de ce plan.
- Missions existantes inchangées ; les 8 leviers existants inchangés.
- Ton : jamais culpabilisant ; « ce n’est pas ta faute » ; responsabilité toujours du côté de l’auteur ; le joueur n’envoie jamais d’image intime ; aucun vocabulaire sexuel explicite ; le 3018 cité.

## Review Focus

1. **Fuite d’un brouillon en production** : `buildContent({ brouillons: false })` exclut toute mission sensible `a-relire` ; le thème reste « Bientôt disponible ». Test tâche 2 (+ vérification du bundle de prod à la tâche 7).
2. **Mission sensible sans `relecture`, ou `relue-interne` sans `par`/`date`** : refusée au build avec un message clair. Test tâche 2.
3. **Message qui minimise dans « Soutenir »** (« Laisse tomber… ») et **excuse qui n’en est pas une** dans « Retirer la publication » : expliqués sans être interdits, l’élève peut toujours finir. Tests tâche 3.
4. **Formule culpabilisante** dans une conséquence, un indice, un « À retenir » ou une réaction : détectée par le test de liste noire, sauf « ce n’est pas ta faute ». Test tâche 4.
5. **Fin de mission sensible sans levier cédé** : texte neutre « Tu as fait les bons choix cette fois. Ce qui peut faire hésiter : ». Test tâche 1.

## Règles d’écriture (tâches 5 et 6)

Lire le § 5 et le § 6 de la spec : ils sont la source des situations, des rôles, des mini-jeux et des récupérations. Toutes les règles de contenu existantes s’appliquent (README « Écrire une mission ») et les règles éditoriales de la tâche 4. En plus :
- `relecture: { statut: a-relire }` sur chaque mission ; `fiche.siRevelation` complet (écouter sans promettre le secret, ne pas interroger, prévenir CPE, infirmier·e et chef d’établissement, protocole pHARe, information préoccupante si besoin) ; `fiche.deroulement` en 5 lignes.
- 3 scénarios + 1 mini-jeu (`tri` pour `harcelement`, `repere` pour `rencontres`), `pourquoi` de 3-4 leviers (les nouveaux leviers sont faits pour ces thèmes), récupération sur **chaque** scénario qui a un choix risqué : victime → `capture-preuve` ; témoin → `soutenir` ; auteur → `retirer-publication` ; contact inquiétant / chantage → `bloquer-signaler`.
- Le choix `aide` nomme un adulte concret ou le 3018, et sa conséquence dit ce qui se passe ensuite (écoute, retrait du contenu, protection).
- Le choix risqué reste une vraie pensée d’ado mais n’est jamais présenté comme la cause de ce qui arrive : la responsabilité est du côté de l’auteur.
- Le joueur n’envoie jamais d’image intime ; le chantage passe par un montage, un bluff ou une confidence d’ami. Aucun vocabulaire sexuel explicite.
- Harcèlement scolaire = délit (loi du 2 mars 2022) : dit aux lycéens et dans la fiche enseignant, sans menacer les plus jeunes.
- Marques et pseudos fictifs, numéros fictifs ; 6e ≤ 20 mots par phrase et versions simplifiées ; choix risqué pas systématiquement le plus long ni repérable à sa forme.
- Vérification : `npx vitest run && npx vite build` ; puis relecture par un adulte de l’âge visé (ton), puis comme enseignant.
